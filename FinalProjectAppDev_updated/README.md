# ITern

Student–company internship matching platform. Node.js/Express + MySQL backend,
plain HTML/CSS/JS frontend, Python (FastAPI) ML matching service.

See `CHANGELOG_REVISION.md` for the history of fixes made in the current
revision pass.

## Project structure
```
backend/    Express API + MySQL
frontend/   Static HTML/CSS/JS — student/ and company/ portals
ml/         Python FastAPI service — resume skill extraction + match scoring
```

## First-time setup (every group member needs to do this once)

### 1. Clone and get the database running
```bash
git clone <repo-url>
cd <repo-folder>
```
Set up MySQL locally and run the schema (ask whoever has `schema.sql` /
migration files for the current version, or check `backend/db/`). Create the
`itern_app` MySQL user with a password **you choose** — it does not need to
match anyone else's, since each person's `.env` is local and never committed.

### 2. Backend
```bash
cd backend
copy .env.example .env      # Windows — or `cp .env.example .env` on Mac/Linux
npm install
```
Edit `.env` and fill in **your own** `DB_PASSWORD` and a random `JWT_SECRET`.
Then:
```bash
npm run dev
```

### 3. ML service
```bash
cd ml
copy .env.example .env      # fill in the SAME DB_PASSWORD you used in backend/.env
python -m venv venv
venv\Scripts\activate        # Mac/Linux: source venv/bin/activate
pip install -r requirements.txt
python -m uvicorn skill_matcher:app --reload --port 8000
```
You do **not** need to retrain the model — `models/proficiency_model_pure.json`
is already included and committed. Only run `train_proficiency_model.py` if
you specifically want to change the training data (that needs the extra
packages in `requirements-training.txt`).

### 4. Frontend
```bash
cd frontend
python -m http.server 5500
```
Open **`http://127.0.0.1:5500`** in your browser — must match `CLIENT_ORIGIN`
in `backend/.env` exactly, or every request gets blocked by CORS.

## Never commit
- `backend/.env` or `ml/.env` (real passwords/secrets — already in `.gitignore`)
- `backend/node_modules/` or `ml/venv/` (huge, regenerated by `npm install` / `pip install`)

## Working as a group — a couple of ground rules worth agreeing on
- Everyone works on a **branch**, not directly on `main`:
  ```bash
  git checkout -b your-name/short-feature-description
  ```
  Push that branch and open a Pull Request into `main` rather than pushing
  straight to `main` — this avoids two people's changes silently overwriting
  each other, which is the most common way group projects lose work right
  before a deadline.
- Pull before you start working each session (`git pull origin main`) so
  you're not building on stale code.
- If two people touch the same file, expect a merge conflict — that's normal,
  not a sign something's broken. Ask before force-pushing anything.
